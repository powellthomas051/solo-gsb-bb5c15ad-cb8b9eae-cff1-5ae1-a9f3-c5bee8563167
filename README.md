# 字幕断句(Subtitle Segmenter)

基于 FastAPI + 原生 HTML/JavaScript 的字幕断句网页应用。用户粘贴带时间戳的词序列,可标记不可拆短语、按词间隙设置边界约束;系统在「每条最多两行、行宽与阅读速度限制」下,用全局动态规划选择分段,使 **镜头切点偏差 + 行长不均 + 不自然停顿** 的加权总代价最低。页面实时展示断句预览与逐段代价,调整权重或边界约束即时重算;无可行方案时定位首个冲突区间(或首个不可行边界)及具体原因并高亮。请求 `alternatives`(1～5,默认 1)大于 1 时,后端用 **K-best 动态规划** 返回总代价从低到高的备选方案,可在页面切换并突出与最优方案不同的断点。还可在预览中**锁定任意字幕段**:再次调整权重、边界约束或备选数量时,后端固定这些段的词范围与内部换行,只优化其余区间。此外提供**术语一致性审校**:维护「规范写法 + 多个识别变体」术语表,对当前选中的断句方案做 NFKC/大小写归一审校,跨词不跨段收集命中,重叠候选由区间动态规划唯一选取,页面按字幕段高亮并可下载审校 JSON。

## 启动

```bash
docker compose up --build
```

依赖安装与应用初始化均随容器启动自动完成,无需本地环境。

## 访问

`docker compose up --build` 启动容器后,浏览器打开 http://localhost:8000 即可使用;后端同时提供:

- 网页界面: http://localhost:8000
- 交互式 API 文档(Swagger UI): http://localhost:8000/docs
- 断句接口: `POST http://localhost:8000/api/segment`
- 术语一致性审校接口: `POST http://localhost:8000/api/review`

## 边界约束

在「词序列 · 边界约束」面板中,点击两个词之间的间隙即可设置硬约束,再次点击循环切换,第三次点击清除:

| 标记 | 类型 | 含义 |
| --- | --- | --- |
| 红色竖线 | `must_break` | 必须断开:分段边界必须落在该间隙 |
| 绿色横线 | `no_break` | 禁止断开:间隙两侧的词必须落在同一段 |
| 紫色细线 | (不可设置) | 不可拆短语内部的间隙,不允许设置边界 |

约束随请求提交,在全局动态规划中作为硬条件生效。若约束导致无可行方案(例如必须断开后任一侧违反时长、行宽或阅读速度限制),响应返回**首个不可行边界**及具体原因,页面保留输入与标记,并高亮冲突边界与冲突词区间;调整约束或权重后即时重算。

## 锁定段(锁定后局部重算)

在「断句预览」中,每段右上角有 **🔒 锁定** 按钮。点击后该段的**词范围与内部换行位置**被固定(青色描边 + 🔒 标记,词序列预览中以青色标出锁定词范围与锁边界);再次点击(或冲突面板中的「解锁」)可解除。

- 锁定后调整**权重、边界约束、镜头切点或备选数量**,后端把锁定段的两个段边界转为 `must_break`、锁内词间隙转为 `no_break`,并以锁定换行作为该段唯一合法布局,**只优化锁定段之外的区间**;各自由区间与锁定段的组合仍在**同一张全局分段 DAG** 上做 K-best 动态规划 —— 跨区间组合按**全局总代价统一排序**,并按**完整断点序列去重**(全局总代价相同时按断点序列兜底判重),因此锁定不影响「K-best 全局最优」的语义,备选数量 1～5 的行为不变。
- 锁定段本身不再受权重变化影响(词范围、两行文本逐字保持);自由段的断点与换行照常优化。每段响应新增 `line_break`(段内换行处的词间隙下标,单行为 `null`)与 `locked` 标记(仅锁定段携带)。
- 下列情况锁定段**失效**,响应返回 `ok: false` 与**首个**冲突锁及具体原因,页面把问题段标红闪烁、在冲突面板中列出全部锁定段并保留锁定状态,可直接解锁或修正输入后自动重算:
  - **锁定段互相重叠**(首尾相接允许);
  - 词序列增删后锁定**词范围越界**、起点/终点落入不可拆短语内部;
  - 不可拆短语变化后,锁定的**内部换行落入短语内部**;
  - 锁定段(含锁定换行)在新参数下违反行宽、时长或阅读速度硬约束;
  - 锁定边界 / 锁内间隙与用户新设置的 `no_break` / `must_break` 约束冲突。
- 未传 `locks` 字段(或为空数组)时,请求与响应结构与旧版完全一致(仅每段多出恒存在的 `line_break` 字段)。

## 术语一致性审校

在左侧「术语表 · 术语一致性审校」面板维护术语表,每行一个术语:

```
规范写法 = 识别变体1 | 识别变体2 | …
```

例如 `动态规划 = DP | ｄｐ` 表示规范写法为「动态规划」,识别变体有 `DP`、`ｄｐ`;不写 `=` 时该行视为只有规范写法的术语。审校始终针对**当前选中的断句方案**(备选方案切换后自动重审),修改术语表即时重算。

- **归一化**:规范词、变体与字幕文本先做 **NFKC 归一**(全角 `ＤＰ` → `DP`、兼容字符合并)与**大小写归一**(`DP`/`dp` 视为同一识别串),再折叠空白。
- **命中范围**:命中可以**跨词**(中文规范词被切成多个词,如「人工」「智能」;或英文多词 `dynamic programming`),但**不跨字幕段** —— 仅在每段所辖词的窗口内收集命中,段间缝隙上的跨段串不命中。
- **嵌套/重叠消解**:同一位置出现多个候选(嵌套或重叠)时,**不按术语逐个匹配定夺**,而是把全部候选放入「加权区间调度」**区间动态规划**,选一个非重叠集合,字典序目标为:
  1. 覆盖归一字符数最多(长术语压过其内部的短术语);
  2. 覆盖中**非规范变体命中数最少**(规范写法与变体同位置时取规范);
  3. 再按**术语录入顺序**(及变体录入顺序、起点)稳定决胜,保证结果唯一、不依赖候选枚举顺序。
- **页面展示**:预览中的字幕段按词高亮命中 —— **绿色**为规范写法、**橙色**为变体(悬停显示应改写成的规范词);面板汇总命中总数、规范次数、变体次数,并按术语列出各变体出现次数,存在变体命中的术语列入**不一致项**(术语序号)。点击「下载审校 JSON」可把完整审校结果保存为 `terminology-review.json`。
- **术语表问题不吞输入**:某个术语**规范词归一后为空**,或**同一识别串归属冲突**(两个不同术语把同一归一写法用作规范词或变体)时,审校不执行,返回错误**术语序号**(归属冲突同时给出先录入的一方序号与冲突识别串)与完整术语表回显;页面保留术语表原文并标出问题序号。
- 术语表为空或当前无断句方案时不发起审校;审校接口独立于断句接口,**现有断句行为与 `/api/segment` 请求/响应完全兼容,不受影响**。


## 配置

无需环境变量;所有参数在网页左侧面板调整(也可通过 API 的 `config` 字段传入):

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `max_chars_per_line` | 42 | 单行最大字符数(硬约束,每段最多 2 行) |
| `max_cps` | 20 | 最大阅读速度,字/秒(硬约束) |
| `min_duration` | 0.8 | 每段最短时长,秒(硬约束) |
| `max_duration` | 7.0 | 每段最长时长,秒(硬约束) |
| `pause_threshold` | 0.3 | 词间间隔小于该值视为不自然断点,秒 |
| `shot_dev_cap` | 0.5 | 镜头切点偏差归一化上限,秒 |
| `crossing_penalty` | 1.0 | 分段跨越一个镜头切点的惩罚 |
| `w_shot` | 1.0 | 权重:镜头切点偏差 |
| `w_imbalance` | 1.0 | 权重:行长不均 |
| `w_pause` | 1.0 | 权重:不自然停顿 |

## 输入格式

- **词序列**:每行 `开始 结束 文本`,时间支持 `HH:MM:SS.mmm` 或秒数;也接受 JSON 数组 `[{"text","start","end"}]`。
- **不可拆短语**:每行一个,词下标区间(如 `3-6`,含端点)或短语原文(自动匹配首个连续出现)。
- **边界约束**:在词序列预览中点击词间间隙设置(见上节);约束按词间隙下标解释,修改词序列后请核对位置。
- **镜头切点**:每行一个时间点。

## API

`POST /api/segment`,请求体:

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "phrases": [[4, 5, 6]],
  "shots": [4.5, 8.0],
  "boundaries": [{"index": 7, "type": "must_break"}, {"index": 10, "type": "no_break"}],
  "locks": [{"word_range": [3, 7], "line_break": 5}],
  "alternatives": 3,
  "config": {"max_cps": 20, "w_shot": 1.0}
}
```

- `words`(必填):词序列,含 `text` / `start` / `end`(秒)。
- `phrases`(可选,默认 `[]`):不可拆短语的词下标区间(连续、含端点)。
- `shots`(可选,默认 `[]`):镜头切点时间(秒)。
- `boundaries`(可选,默认 `[]`):词间隙边界约束。`index = k` 表示词 `k-1` 与词 `k` 之间的间隙(`1 <= k <= len(words)-1`);`type` 为 `must_break`(必须断开)或 `no_break`(禁止断开)。同一间隙不得同时设置两种类型;间隙不得位于不可拆短语内部,否则返回 422。**不传该字段时行为与旧版完全一致。**
- `locks`(可选,默认 `[]`):锁定段数组,每项 `{"word_range": [a, b], "line_break": k}`:`word_range` 为含端点的词下标区间,`line_break` 为段内换行处的词间隙下标(`k` 在 `(a, b]` 内,即词 `k-1` 与词 `k` 之间换行),传 `null` 表示锁定为单行。重算时锁定段的词范围与两行文本逐字保持,只优化其余区间;跨区间的 K-best 组合仍按全局总代价排序、按完整断点序列去重。锁定段之间不得重叠(首尾相接允许);`a`/`b` 必须是词序列或不可拆短语的合法边界,`line_break` 不得落在短语内部。**不传或为空数组时请求/响应与旧版一致。**
- `alternatives`(可选,默认 `1`,取值 1～5):请求的备选方案数。全部硬约束(行宽、行数、阅读速度、时长、不可拆短语)、边界约束(`must_break` / `no_break`)与锁定段对所有方案一视同仁;后端在分段 DAG 上做 K-best 动态规划,按**分段边界序列判重**,返回总代价从低到高的互不重复方案(所有备选方案包含完全相同的锁定段)。不足 `alternatives` 个时返回实际数量(最少 1 个,即至少有一个可行方案时)。
- `config`(可选):见「配置」表,未传字段取默认值。

响应:

- 可行:`{"ok": true, "total_cost": ..., "segments": [...]}`;当且仅当 `alternatives > 1` 时额外含 `alternatives` 数组,第 0 项即顶层最优方案(`cost_delta` 为 0):
  ```json
  {"ok": true, "total_cost": 2.6667, "segments": [...],
   "alternatives": [
     {"segments": [...], "total_cost": 2.6667, "cost_delta": 0.0},
     {"segments": [...], "total_cost": 2.7, "cost_delta": 0.0333}
   ]}
  ```
  每项含 `segments`(结构与顶层 `segments` 相同)、`total_cost`(总代价)和 `cost_delta`(与最优方案的总代价之差,按未取整代价计算后四舍五入到 4 位小数,故可能与取整后两项之差相差 0.0001);顶层 `total_cost` / `segments` 始终代表最优方案,因此不传 `alternatives` 或传 1 时响应与旧版完全一致。每个 `segment` 字段:

  | 字段 | 说明 |
  | --- | --- |
  | `word_range` | `[首词下标, 末词下标]` |
  | `start` / `end` / `duration` / `cps` | 起止秒、时长、字符/秒 |
  | `lines` | 一行或两行文本(锁定段为锁定时的原文,逐字保持) |
  | `line_break` | 段内换行处的词间隙下标(单行为 `null`),可直接作为再次请求的 `locks[].line_break` |
  | `cost` | 各代价项与合计 |
  | `locked` | 仅当该段是请求中的锁定段时出现,值为 `true` |

- 不可行:`{"ok": false, "conflict": {...}}`(不含 `alternatives`),`conflict` 含冲突区间 `word_range` / `start` / `end` / `text` / `reasons`(具体违例,如「时长 0.30s 低于下限 0.8s」);若不可行由边界约束导致,另含 `boundary: {"index", "type"}`,即首个不可行边界。
- 锁定段冲突时,`conflict` 额外含 `"kind": "lock"` 与 `"lock": {"word_range": [a, b], "line_break": k}`(回显**首个**问题锁的请求值,可能越界),`reasons` 给出具体原因,典型如:
  - `锁定段(词 3–6)与已锁定段(词 0–3)重叠,请先解锁其中一段`
  - `锁定段词范围 [8, 12] 越界(合法范围 0–9),词序列已变化,请解锁后重新锁定`
  - `锁定段起点词 3 位于不可拆短语内部,不能作为段边界,请解锁后调整(短语已变化)`
  - `锁定段的内部换行词间隙 5(词 4 与词 5 之间)位于不可拆短语内部,不能换行,请解锁后调整`
  - `锁定为单行后长度 55 超过单行上限 42 字符` / `锁定的内部换行(词间隙 5)使行长 48 超过单行上限 42 字符`
  - `锁定段内部词间隙 2 被设置为必须断开,与锁定段词范围冲突`
  - `锁定段(词 2–6)固定了其边界(词 1 与词 2 之间必须断开), 但左侧区间(词 0–1)在当前参数下无可行分段; 请调整权重/约束或解锁该段`(锁本身合法,但锁定边界迫使相邻自由区间在新参数下不可行;此时同时回显 `boundary`)

### `POST /api/review` — 术语一致性审校

对给定断句方案的各段执行术语一致性审校。请求体:

```json
{
  "words": [{"text": "我们", "start": 0.5, "end": 0.9}],
  "segments": [{"word_range": [0, 3]}],
  "terms": [
    {"canonical": "动态规划", "variants": ["DP", "ｄｐ"]},
    {"canonical": "人工智能", "variants": []}
  ]
}
```

- `words`:词序列(结构同 `/api/segment`,审校只用 `text`)。
- `segments`:参与审校的字幕段,每项只需 `word_range: [首词, 末词]`(含端点),必须按词下标递增、互不重叠(首尾相接允许),否则返回 422。前端传当前选中方案的全部段。
- `terms`:术语表,按**录入顺序**给每个术语隐式编号 1、2、…;`canonical` 为规范写法,`variants` 为识别变体(可空)。匹配先做 NFKC + 大小写归一与空白折叠;命中可跨词、不跨段;重叠候选由区间动态规划按「覆盖字符最多 → 变体最少 → 录入顺序」唯一选取。

成功响应(即页面「下载审校 JSON」的内容):

```json
{
  "ok": true,
  "canonical_count": 2,
  "variant_count": 1,
  "hit_count": 3,
  "inconsistent": [1],
  "segments": [
    {"index": 0, "word_range": [0, 3], "hits": [
      {"term_index": 1, "canonical": "动态规划", "kind": "variant",
       "variant": "DP", "word_range": [3, 3], "text": "dp"}]}
  ],
  "terms": [
    {"term_index": 1, "canonical": "动态规划",
     "canonical_count": 1, "variant_count": 1,
     "variants": [{"variant": "DP", "count": 1}]}
  ]
}
```

- 顶层 `canonical_count` / `variant_count` / `hit_count`:规范、变体(不一致)与全部命中次数;`inconsistent` 为出现变体命中的术语序号列表。
- `segments[].hits[]`:按字幕段给出的命中,`kind` 为 `canonical` 或 `variant`,`word_range` 为命中覆盖的词下标区间(可跨词,不跨段),`text` 为命中处的原文拼接,变体命中另带 `variant`(用户录入原文)。
- `terms[]`:按术语序号汇总的规范/变体次数,`variants` 按变体录入顺序给出各变体次数。

术语表问题时返回 HTTP 200、`ok: false`,并**回显完整术语表输入**(`terms`),供调用方保留用户输入:

```json
{"ok": false, "error": {"kind": "empty_canonical", "term_index": 2}, "terms": [...]}
{"ok": false, "error": {"kind": "variant_conflict", "term_index": 2,
  "owner_index": 1, "pattern": "AI"}, "terms": [...]}
```

| `error.kind` | 含义 |
| --- | --- |
| `empty_canonical` | 第 `term_index` 个术语的规范写法归一后为空 |
| `variant_conflict` | 第 `term_index` 个术语的识别串 `pattern` 已归属第 `owner_index` 个术语(同一归一写法不得归属两个术语) |

## 备选方案(页面)

在「约束与权重」面板把**备选方案数量**设为大于 1 后,断句预览顶部出现方案切换条:`最优方案` 与 `方案 2…N`,非最优按钮标注相对代价增量(如 `+0.0333`)。切换后:

- 预览分段、逐段代价与总代价随所选方案更新;
- 词序列中用蓝色竖线标出当前方案断点,与最优方案不同的断点用**橙色**加粗竖线;最优方案有、当前方案没有的断点用蓝色空心圆标出(用户手动设置的必须断开 / 禁止断开标记不被覆盖);锁定段边界始终用青色竖线标出;
- 段首断点与最优方案不同的分段以橙色描边并标注「断点不同于最优」;
- 已锁定段在每个备选方案中保持同一段,以青色描边并标注「🔒 已锁定」;
- 只有一个可行方案时显示「只有一个可行方案,无更多备选」。
